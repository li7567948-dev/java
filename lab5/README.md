# Лабораторная работа №5 — создание графического приложения на Java2D

**Тема:** графическая визуализация результатов лабораторной работы №3: исследование производительности коллекций `ArrayList` и `HashMap`.

## Проверенные исходные данные

При разработке использованы результаты уже выполненной ЛР3 в GitHub-репозитории студента `li7567948-dev/java`:

- `lab3/results/summary.csv` — реальная сводка измерений для 10, 100, 1000, 10000, 100000 элементов;
- `lab3/src/controller/BenchmarkService.java` — формулы вычисления суммарного и среднего времени;
- `lab3/src/controller/ErrMsgLog.java` — формат исходных логов;
- `lab3/README.md` и `lab3/复查说明_2026-11-09.md` — исправления и обоснование интерпретации результатов.

**Важно:** в ЛР3 применены операции `ArrayList.add / ArrayList.set` и `HashMap.put / HashMap.replace`, **не** `remove`. Поэтому на графиках показано **изменение элемента**, а не удаление. Подписи не искажают смысл измерений. Все времена выражены в **наносекундах**. В диаграммах используются зафиксированные реальные результаты ЛР3; генерации случайных чисел вместо данных нет.

Исходная CSV скопирована **без изменения чисел** в `data/lab3_summary.csv`. Также включён `data/lab3_ready.lab5` — тот же набор измерений с настройками графика в одном файле. Полные пооперационные журналы из старого проекта доступны в ранее созданном архиве `lab3/results/10_performance_logs.zip` в [исходном GitHub-репозитории](https://github.com/li7567948-dev/java/blob/main/lab3/results/10_performance_logs.zip). Они не подменены выдуманными журналами в этой выдаче.

## Запуск в Eclipse (основной способ)

1. Распаковать ZIP в отдельную папку, не смешивая содержимое с `lab2` и `lab3`.
2. Открыть **File → Import → General → Existing Projects into Workspace → Next**.
3. Нажать **Select root directory** и указать папку `lab5`, в которой лежат `.project` и `.classpath`.
4. Нажать **Finish**; проверить JDK 8 или новее.
5. Выполнить **Project → Clean**, чтобы Eclipse пересобрал классы.
6. В Package Explorer открыть `src/lab5/Main.java`, затем **Run As → Java Application**.
7. Откроются **4 графика** с данными `data/lab3_summary.csv` (загружаются автоматически).

Дополнительно на Windows можно запустить `run_windows.bat` (должен быть установлен JDK, `javac` доступен через `PATH`).

### Командная строка

В папке `lab5`:

```sh
javac -encoding UTF-8 -d bin src/lab5/model/*.java src/lab5/io/*.java src/lab5/view/*.java src/lab5/tests/*.java src/lab5/Main.java
java -cp bin lab5.Main
java -ea -Dfile.encoding=UTF-8 -cp bin lab5.tests.Lab5Tests
```

Команда `java -cp bin lab5.Main data/lab3_ready.lab5` загружает выбранный файл по аргументу. Можно указать несколько путей.

## Функции в точном соответствии с условием №5

| Требование | Где реализовано | Как продемонстрировать преподавателю |
|---|---|---|
| 1. Изменение масштаба | `GraphPanel`, `MainFrame` | Ползунок, кнопки `+`, `−`, колёсико мыши; перетаскивание для сдвига, сброс |
| 2. Легенда | `GraphPanel.paintLegend` | Включить/отключить флажок `Легенда`; цвет каждого ряда показан отдельно |
| 3. Линейные/логарифмические оси | `GraphPanel.drawX/drawY`, `ViewSettings.Scale` | Независимо менять `Ось X` и `Ось Y` |
| 4. Загрузка графика из файла | `MeasurementFileService.read` | Открыть `CSV`, исходные `LOG` ЛР3 либо сохранённый `.lab5` |
| 5. Раздельный/совместный показ | `MainFrame.redraw`, `GraphPanel.createSeries` | Выбрать `Раздельно` или `Совместно`. Десять LOG ЛР3 объединяются в **две непрерывные серии из пяти точек** |
| 6. Локальные значения | `GraphPanel.getToolTipText` | Навести мышь на кружок: источник, N, время операции |
| 7. Повторное открытие со старыми настройками | `MeasurementFileService.saveBundle/saveSettings` | Сохранить `.lab5` (числа **и** настройки в одном файле) и открыть его снова |

**Четыре графика:** среднее время добавления, общее время добавления, среднее время изменения, общее время изменения. Все четыре построены по пяти значениям `N` для двух коллекций. `Median` читается и сохраняется для целостности данных, но по заданию ЛР5 является вспомогательным, а не пятой обязательной диаграммой.

## Как сохраняются настройки

- **`Сохранить данные + настройки...`**: один переносимый файл `.lab5`, в котором записаны измерения всех загруженных файлов и настройки масштаба, видимости легенды, осей X/Y. **Это основной режим для демонстрации пункта 7.**
- **`Сохранить настройки`**: для исходных `*.csv` и `*.log` рядом создаётся файл `имя.csv.view.properties` / `имя.log.view.properties`. Сам лог **не переписывается**, чтобы не нарушать данные ЛР3. Для файлов `.lab5` параметры сохраняются непосредственно внутри самого файла.
- При открытии файла ранее сохранённые настройки применяются автоматически.
- В режиме объединённого просмотра текущие параметры сохраняются для всех открытых файлов; в раздельном режиме переключение между файлами восстанавливает настройки выбранного файла.

## Архитектура, обработка исключений и качество

```text
src/lab5/Main.java                    — вход в EDT через EventQueue.invokeLater
src/lab5/view/MainFrame.java          — JFrame, элементы управления, события
src/lab5/view/GraphPanel.java         — JComponent, Graphics2D, paintComponent
src/lab5/model/Measurement.java       — неизменяемая запись результатов и четыре метрики
src/lab5/model/DataFile.java          — данные файла и собственные настройки
src/lab5/model/ViewSettings.java      — масштаб, легенда и оси
src/lab5/io/MeasurementFileService.java — UTF-8 CSV/LOG/LAB5, сохранение без порчи логов
src/lab5/io/ErrorHandler.java         — единая обработка ошибок, счётчик, журнал ошибок
src/lab5/tests/Lab5Tests.java         — регрессионные тесты (без JUnit)
src/lab5/tests/GuiSmokeTest.java      — проверка Swing-окна при наличии экрана
```

Использован **Java Swing и Java2D**, без JavaFX, сторонних библиотек, Python и внешних графических API. При рисовании переопределён `paintComponent`, вызывается `super.paintComponent`, создаётся копия `Graphics2D` и она корректно освобождается. Объекты измерений неизменяемы; сведения о времени проверяются до отображения. GUI создаётся в потоке событий EDT, а чтение больших журналов выполняется вне EDT через `SwingWorker`. Ошибки показываются пользователю и регистрируются централизованно, без подмены результатов.
