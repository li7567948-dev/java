# Лабораторная работа № 3

**Дисциплина:** Основы Java  
**Тема:** Работа с исключениями и коллекциями  
**Разрабатываемое приложение:** Пункт пропуска автомобилей (продолжение ЛР № 2)

## Цель

Освоить обработку исключительных ситуаций в Java, создать коллекции объектов своего класса и экспериментально сравнить временные характеристики операций добавления и изменения.

## Постановка задачи

Исходный вариант ЛР № 2 моделирует пропуск автомобилей: пять наследников `Vehicle`, объекты проверки `CheckPoint`, очередь автомобилей и события `Simulation`.

**Главный класс ЛР № 3 — `Simulation`**, поскольку он содержит коллекцию пунктов пропуска и очередь объектов различных наследников `Vehicle`. Выполнены две коллекции:

```java
ArrayList<Simulation> simulations = new ArrayList<Simulation>();
HashMap<Integer, Simulation> simulationsById = new HashMap<Integer, Simulation>();
```

## Реализация

1. `SimulationCollections` содержит два варианта коллекций одного главного типа. При заполнении для обоих вариантов сохраняется одна и та же ссылка на очередной объект.
2. `Lab3ObjectGenerator` создаёт новые `Simulation` со случайным количеством пунктов (1–3) и машин (1–2). Методы `generateCar`, `generateTruck`, `generateBus`, `generateTrailer`, `generateCarWithTrailer` создают все типы из ЛР2. Также реализованы генераторы связанных `CheckPoint`, `Event`, `CheckResult`, `Generator`.
3. `BenchmarkService` отдельно измеряет операции над `ArrayList` и `HashMap`, по 5 размерностям N = 10, 100, 1000, 10000, 100000. После заполнения изменяются 10% случайно выбранных уникальных индексов/ключей.
4. Для каждого измерения используется `System.nanoTime()`. Операции генерации данных и записи файла вынесены за границы измеряемого интервала. Записи имеют вид `add, ID = 1, 123` и `replace, ID = 1, 321` (единица: нс).
5. `ErrMsgLog` — класс централизованной обработки ошибок с отдельным счётчиком и журналом ошибок. Он же отвечает за запись 10 протоколов производительности.
6. Средние арифметические и медианы рассчитываются независимо; в каждом логе приведены полные суммы времени для каждого типа операций и общий итог.
7. `ArrayListCapacityStudy` непосредственно сравнивает время добавления в `ArrayList`, созданный с явно заданной ёмкостью, до заполнения и при первом добавлении сверх ёмкости. Формула из пособия `(oldCapacity * 3) / 2 + 1` используется как историческое расчётное значение следующего размера; публичный API не позволяет по времени доказать фактический размер внутреннего массива.

## Режим разрешимости

Режим запускается отдельно: `java controller.Main --solvability` для воспроизводимого примера, либо пунктом меню 5 для ввода своих параметров. Алгоритм перебирает исходный, восходящий и нисходящий порядки проверок, а также варианты открытия существующих резервных пунктов; найденное решение повторно проверяется симуляцией. Отсутствие решения в этих вариантах не является доказательством математической невозможности других порядков. Для демонстрации используется четыре трейлера по 4 минуты каждый, один работающий и один резервный пункт. При одном пункте требуется 16 минут. Открытие второго физически существующего пункта сокращает время до 8 минут, то есть позволяет завершить проверку к заданному сроку 10 минут. Расчёт основан на методах `Simulation.step()` и `Vehicle.getCheckTime()`.

Не допускаются предложения об уменьшении времени проверки до нуля, увеличении скорости движения сверх норм или создании несуществующих пунктов.

## Результаты эксперимента

Полные журналы расположены в `logs/ArrayList_*.log` и `logs/HashMap_*.log`, все десять размеров/типов; таблица результатов — `results/summary.csv`.

Среднее время операции: \(\overline{t} = \frac{\sum_{i=1}^{n} t_i}{n}\). Суммарное время: \(T = \sum_{i=1}^{n} t_i\). Медиана хранится отдельно под `*MedianTime`.

Сопоставление значений `Total` и `Median` при росте размеров и сравнении `ArrayList` и `HashMap` приведено в `results/conclusion_ru.txt`. Таблица `results/summary.csv` содержит оба показателя для добавления и изменения. Данные могут изменяться при новом запуске в силу JIT, GC и нагрузки на компьютер.

## Вывод

В ЛР № 3 разработано продолжение программы «Пункт пропуска автомобилей» из ЛР № 2. Реализованы две коллекции главного класса `Simulation`, генерация классов модели, обработка исключений, десять экспериментальных логов, анализ операций и проверяемый режим разрешимости. Проведено сравнение временных характеристик операций по полным и средним значениям. Старый пример формулы роста `ArrayList` не используется как недоказанный факт для современных JVM.
