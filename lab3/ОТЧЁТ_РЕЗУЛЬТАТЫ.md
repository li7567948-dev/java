# Лабораторная работа №3. Анализ результатов

**Тема:** работа с исключениями и коллекциями Java. **Объект модели:** пункт пропуска автомобилей (`Checkpoint`).

## Цель работы

Исследовать работу двух разных коллекций (`ArrayList` и `HashMap`), продемонстрировать создание объектов собственного класса, обработку ошибок и измерение времени операций.

## Ход работы

1. Создан класс `Checkpoint` с набором объектов типа `Vehicle` и контрольных полос `InspectionLane`. Для автомобилей использована иерархия `Vehicle` → `PassengerCar`, `Bus`, `Truck`.
2. Реализованы генераторы случайных объектов класса `Checkpoint`, а также связанных классов.
3. Выполнено заполнение `ArrayList<Checkpoint>` и `HashMap<Integer, Checkpoint>` с 10, 100, 1000, 10000, 100000 элементами.
4. Для каждой коллекции случайным образом выбраны 10% различных индексов и выполнены изменения `set` / `replace`.
5. Время операции измерено с помощью `System.nanoTime()`. В каждом журнале сохранены тип операции, индекс и время, а также суммарное время, среднее арифметическое и медиана по типу операций.
6. Через `ErrMsgLog` реализованы вывод сообщений, сохранение журналов и счётчик ошибок.
7. В режиме разрешимости проверено прохождение очереди через совместимые полосы контроля за заданное время.

## Выводы

`ArrayList` обеспечивает доступ к элементу по индексу и быструю замену существующего элемента с помощью `set`. При увеличении размера коллекции общая длительность серии добавлений закономерно возрастает прежде всего из-за роста числа выполненных операций. Для `HashMap` замена значения производится по ключу через `replace`, при этом изменение 10% элементов не требует сквозного обхода списка.

Сравнение **суммарного** времени для разных N нужно учитывать совместно с количеством операций (N добавлений, N/10 изменений); для оценки времени отдельной типичной операции используются `MedianTime` и `AverageTime`. В конце каждого лога записываются `allOperationsTotalCount`, `allOperationsTotalTime` и `allOperationsAverageTime`. В конце каждого лога записываются `allOperationsTotalCount`, `allOperationsTotalTime` и `allOperationsAverageTime`. Значения для малых N и одиночных операций нестабильны; на них влияют прогрев JVM, сборка мусора и другие процессы. Поэтому по одному запуску не следует делать вывод о гарантированном превосходстве типа коллекции на всех машинах.

**Пункт 6.** В методичке используется формула роста ёмкости `(oldCapacity * 3) / 2 + 1`. В современных реализациях `ArrayList` применяются иные правила роста (ориентировочно в 1,5 раза); фактическое поведение зависит от версии Java. В файле `logs/ArrayList_capacity_check.txt` сопоставлены длительности `add` около порогов обеих гипотез. У некоторых операций возле предполагаемых расширений есть повышенное время, но данные сами по себе не устанавливают точную внутреннюю ёмкость; для этого нужно исследовать реализацию конкретной версии JDK.

**Пункт 7.2 (разрешимость).** Реализован отдельный режим `--solvability`. Реализован отдельный режим `--solvability`. В контрольном примере 4 грузовика требуют по 8 минут каждый. При одной работающей универсальной полосе и одной полосе только для легковых автомобилей завершение занимает **32 минуты**, что больше лимита **16 минут**. После открытия **уже существующей** резервной универсальной полосы время составляет **16 минут**. Все длительности строго положительные, допуск водителей проверяется. Таким образом, показано реально выполнимое изменение режима работы.

**Итог:** требования по двум типам коллекций, генерации объектов, измерению времени и обработке ошибок демонстрируются в программе. Для защиты следует показать запуск и объяснить различия коллекций, случайный выбор индексов, содержание логов и режим разрешимости. Реальный журнал работы с нейросетью должен быть дополнительно размещён на сетевом диске (см. отдельный файл).


## Ограничения подтверждения соответствия

- Требование пункта 7.3 о **подлинном журнале общения с нейросетью** невозможно выполнить только исходным кодом. Нужно сохранить настоящую переписку и разместить ссылку в указанном преподавателем общем документе.
- Доступа к исходным Java-файлам **последней исправленной ЛР №2** на момент проверки не было. Тема и MVC-структура сохранены, но точное совпадение классов, интерфейсов и исправлений преподавателя **нельзя подтвердить** без сравнения с тем архивом.
- Замеры времени в таблице получены в одном повторном испытании при проверке. При новом запуске время будет отличаться; для точных выводов о скорости нужны многократные повторения.
