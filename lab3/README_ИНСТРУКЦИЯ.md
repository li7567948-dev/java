# Лабораторная работа № 3 — Пункт пропуска автомобилей

Тема: **работа с исключениями и коллекциями Java**. Проект для Eclipse, совместим с Java 8 и новее.

## Запуск в Eclipse

1. Распакуйте архив в отдельную папку.
2. Откройте Eclipse → **File → Import → General → Existing Projects into Workspace → Next**.
3. Выберите папку `Java_Lab3_Checkpoint` → **Finish**.
4. В Project Explorer откройте `src/app/Main.java` → **Run As → Java Application**.
5. По умолчанию сначала выполняется демонстрация коллекций и режима разрешимости, затем создаются 10 журналов измерений в папке `logs`.
6. Для демонстрации пункта 1: задайте аргумент `--demo` в **Run Configurations → Arguments**.
7. Для самостоятельного запуска режима разрешимости используйте `--solvability`. Для создания журналов задайте `--benchmark`. Для полного запуска используется `--all`.

Другой вариант: на Windows с установленным JDK запустить `RUN_WINDOWS.bat`. Для тестов запустить `RUN_TESTS_WINDOWS.bat`.

## Пункт 1 (главное задание)

В `model.CheckpointCollections` созданы обе коллекции одного главного класса:

- `ArrayList<Checkpoint>` — динамический массив;
- `HashMap<Integer, Checkpoint>` — ассоциативный массив, ключом служит индекс.

Класс `Checkpoint` содержит связанные объекты `Vehicle` (иерархия `PassengerCar`, `Bus`, `Truck`) и `InspectionLane`. При заполнении коллекций `model.CheckpointGenerator` создаёт **объекты Checkpoint**, а не строки или числа. Один и тот же созданный объект попадает в обе коллекции для непосредственной проверки равенства ссылок.

## Реализация остальных пунктов методички

**Пункт 2:** генераторы `generateCheckpoint`, `generateVehicle`, `generatePassengerCar`, `generateBus`, `generateTruck`, `generateDriver`, `generateInspectionLane`.

**Пункт 3:** 10 логов по двум типам коллекций с размерами 10, 100, 1000, 10000, 100000. Изменяются **10% различных случайных индексов**. Замеры `System.nanoTime()` непосредственно вокруг `add / put / set / replace`. При создании новых объектов время генерации не включено в замер коллекции. По окончании каждого файла отдельно выводятся суммарное время и среднее время **всех** операций.

**Пункт 4:** класс `controller.ErrMsgLog` записывает данные и централизованно обрабатывает исключения со счётчиком ошибок.

**Пункт 5:** выводы в файле `ОТЧЁТ_РЕЗУЛЬТАТЫ.md`.

**Пункт 6:** файл `logs/ArrayList_capacity_check.txt`. Данные показывают время добавления вблизи предполагаемых порогов, но только по времени нельзя достоверно восстановить внутреннюю ёмкость.

**Пункт 7.1:** генераторы не только главного класса, но и всех связанных классов. **Пункт 7.2:** предусмотрен `SolvabilityService` с отдельным режимом `--solvability` и допустимыми предложениями — изменить порядок проверки либо открыть **существующую** резервную полосу. Искусственного уменьшения времени проверки до нуля нет.

**Пункт 7.3:** требование об исходном логе беседы с нейросетью и ссылке в общем документе не может выполняться кодом Java. См. `ВАЖНО_ЛОГ_НЕЙРОСЕТИ.txt`.
