# Лабораторная работа № 4 — Ввод-вывод. Обработка файлов

Пункт пропуска автомобилей. Продолжение ЛР № 2 с учётом исправлений модели ЛР № 3.

## Запуск
Java 8 или новее. В Eclipse: File → Import → Existing Projects into Workspace → выбрать каталог lab4. Запустить `src/controller/Main.java` как Java Application. Рабочий каталог — корень проекта, кодировка UTF-8. Для Windows также предусмотрен `run_windows.bat` (необходим JDK в PATH).

Учебные реквизиты: `root` / `lab4`. Для оператора указать аргумент программы `config-user.properties` (или выполнить `run_windows.bat config-user.properties`), логин `operator`, пароль `lab4`. Это демонстрационные пароли, не для реальных систем.

## Архитектура
- `model/Vehicle.java`, пять подклассов и `CargoCheck`: абстракция, наследование, инкапсуляция, полиморфизм; сохранены ограничения из ЛР 2/3.
- `model/Simulation.java`: модель очереди, независимые копии, защита занятого пункта от закрытия.
- `model/VehicleDatabase.java`: чтение, запись, добавление, изменение и удаление объектов. Формат TSV в UTF-8 с версией и следующим ID в заголовке. Поля: ID, тип, номер, длина, ширина, высота, масса, скорость, груз, время прибытия. Результат проверки вычисляется заново, а не сохраняется.
- `model/AppConfig.java`: Properties и проверка значений. `model/AppLog.java`: журнал с метками времени, режим добавления.
- `controller/Main.java`: композиция приложения, настройки, аутентификация, старт и завершение. `Controller.java`: обработка меню и проверка полномочий.
- `view/ConsoleView.java`: только ввод и вывод. `tests/AutoTests.java`: контрольные данные и проверка ожидаемых результатов.

## Демонстрация задания
1. Войти под root, убедиться, что автотесты выполняются до вывода меню.
2. Пункт 4: прочитать пять объектов из файла. При первом запуске создаётся демонстрационная БД `data/vehicles.txt`.
3. Пункт 6: добавить два или более объектов; 7: изменить по ID; 8: удалить по ID; 5: сохранить; 4: повторно прочитать; 9/10: вывести список/объект. Изменения 6–8 сразу записываются на диск. При повторном запуске данные сохраняются.
4. Пункты 1–3: проверка готовых и собственных машин, моделирование очереди (в том числе из БД).
5. Пункты 11/12: переключение отладки и запуск автотестов. Для user эти пункты не отображаются и отклоняются даже при прямом вводе номера.
6. Запустить с `config-user.properties`: автотесты и отладка работают и у оператора при соответствующих флагах. Изменить `debug` и `autotests` на false для демонстрации отключения. Основные записи журнала остаются включёнными; DEBUG зависит от флага.
7. Проверить `logs/application.log`: запуск, чтение/запись, ошибки, завершение, результаты тестов и DEBUG. Пароли не записываются. Повторный запуск дополняет журнал.

## Проверка
Компиляция OpenJDK 21 с `javac --release 8 -encoding UTF-8 -Xlint:all` (предупреждения только об устаревшем целевом Java 8). 15 групп автотестов успешно выполнены. Дополнительно пройдены 12 интеграционных сценариев, включая все восемь сочетаний роли и флагов. Нативная компиляция JDK 21 с `-Xlint:all` завершилась без предупреждений. `results/` содержит реальные результаты тестового запуска, демонстрацию root/user, отказ аутентификации, журнал и пример БД. Тесты используют временные файлы, не затрагивая рабочую БД. Фактические протоколы находятся в `results/compile.txt`, `results/autotests.txt` и `results/integration_summary.txt`. Для Eclipse включена конфигурация `Lab4.launch` с UTF-8.

Для отдельного запуска тестов: `java -cp bin tests.AutoTests` или `test_windows.bat`.

Ограничения: рассчитано на один запущенный экземпляр программы; учебная локальная авторизация, не промышленная система безопасности. При невозможности атомарной замены файла используется обычное перемещение с заменой. На Windows/Eclipse непосредственно не проверялось. Рукописные замечания преподавателя в полном объёме недоступны; учтены доступные исправления ЛР 2/3 из репозитория, а не предположения о содержании замечаний.
